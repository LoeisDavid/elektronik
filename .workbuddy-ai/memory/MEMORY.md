# MEMORY.md — ERP Elektronik (C:/laragon/www/elektronik)

## Project
- "ERP Elektronik" — Laravel 13 (PHP ^8.3) ERP/POS for an electronics store. UI + comments in Indonesian.
- Modules: POS, Inventory, Finance (currently only daily cash report / laporan kas).
- DB: MySQL via Laragon. 11 tables, all with UPPERCASE table + column names and string primary keys.

## Toolchain gotcha
- CLI `php` on PATH is 8.1.10 and FAILS composer's platform check (needs >=8.3).
- Use Laragon's PHP 8.5: `/c/laragon/bin/php/php-8.5.4-nts-Win32-vs17-x64/php.exe artisan ...`

## Conventions
- Models use PHP attributes: `#[Table('x', key:..., incrementing:false)]` + `#[Fillable([...])]`. Relations are plain methods returning queries (not Eloquent relation objects).
- Codes are generated by `App\Http\Controllers\Controller::generateCode($DES, $table)` — 2 letters per word + digits, padded to 10 chars.
- Views live in `resources/views/POS/` and `resources/views/Inventory/` (capital I).
- Layout: `layouts.app` -> includes/sidebar + includes/header. Tailwind 4 custom palette defined in `resources/css/app.css` (`@theme`): primary-db #0D1C43, primary-sdb #22396F, secondary-bw #F8F8FF, etc.
- Frontend is vanilla JS per page (no Alpine/Livewire). Toast helper `showToast(msg, type)` in layouts/app.blade.php.

## Core domain: unit-level inventory
- Each physical unit = one `itmdt` row with a unique `BC_OUT` barcode. `BC_IN` = scanned code, `BC_OUT` = generated (`ITM` + yymmdd + 4-digit seq).
- A sale writes one `sts` row per unit (`BC_OUT`), grouped by `acr` header (`REF_NO` = INV0000001...).
- `kas` = one row per business day (PK = TGL): opening, cash/non-cash sales, closing.
- POS cart lives in the session (`cart`, `voucher`, `discount_percent`); `kasirController` scans by BC_OUT.

## Design (Penpot)
- User maintains a Penpot file for this project's UI, driven via the Penpot MCP server (see the
  `penpot-neumorphic-ui` skill for the API gotchas + build/export/verify loop).
- The POS Kasir redesign lives there as board `POS - Kasir / Scan & Verify` (1440x900). A first pass
  added a center "scan & verify hub" (stat cards, last-scanned card, scan-history table) plus a right
  order panel; the user then cut all of that as unnecessary. Final design: sidebar verbatim, then the
  order cart filling the middle as a wide columned table (BARANG / HARGA / DISKON / VOUCHER /
  SUBTOTAL / AKSI), the scan input + a single camera "Scan" button on top with a one-line last-scan
  status under it, and a bottom checkout bar (Subtotal / Diskon / Voucher / payment method / Total /
  Konfirmasi & Bayar).
- Second board `POS - Kasir / Scan Kamera (modal)` shows the webcam-scan modal state (dim overlay +
  camera preview with a scan frame). The camera modal is the fallback; the USB scanner gun is primary.
- Third board `POS - Kasir / Draft Transaksi (modal)` lists saved drafts with a per-row "Lanjutkan"
  (resume) and a delete icon. The bottom bar carries an icon-only "add to draft" button plus a
  "Draft Transaksi" button that opens it.
- Qty steppers are wrong for this domain: one physical unit = one `itmdt` row with a unique `BC_OUT`,
  so qty is always 1. Per-line discount/voucher (`sts.POT_1` / `sts.POT_R`) is what belongs on a row.
- The sidebar is a hard constraint: the user does not want it changed.
- Design preference: this user favours dense, minimal, functional screens over extra panels.
